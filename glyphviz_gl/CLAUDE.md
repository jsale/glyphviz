# glyphviz_gl — shipped feature notes

Loaded when working under `glyphviz_gl/` (viewport, main window, dialogs). Moved verbatim from the root `CLAUDE.md` "Feature Status" on 2026-10-18; the root keeps a one-line index of each entry. Project-wide rules (collaboration notes, data contract, tech stack) stay in the root file.

- **Tags** — text labels attached to nodes, loaded either from inline `text`/`link` columns or a companion tag CSV (`gv_tag.csv` native, `np_tag.csv` for GaiaViz-format files), with URL, local-file, and app-launch link encoding (U key / Alt+click). Per-node `show_text` pins a label on regardless of the scene-wide tag settings; the World node's `tag_color_mode` / `tag_color_r/g/b` / `tag_font_size` style every label. **Tag Text Size (2026-08-18)**: `Node.tag_font_size`, another World-row scene setting on the same pattern as the colors — Properties > Display slider (6-36 pt), read by `Viewport._tag_font_size()` (which clamps, since a Channels track or a hand-edited CSV can put anything in the field) and applied in the one place both the mono and stereo tag passes build their painter, `Viewport._tag_painter()`. `TAG_DEFAULT_FONT_SIZE` = **11**, raised from the 9 pt labels were hardcoded to (Jeff found that too small); it is also the load default, so every existing scene simply gets bigger type with no file change — and since the column is only written when != 11, all 53 examples stay column-stable. Bindable as a Channels attribute. Tests: `tests/test_tag_font_size.py` (the last one measures real painted ink through `_paint_tags`, so the setting is pinned to actual pixels, not just to a number moving between objects). **Tag display defaults (2026-08-28)**: `Viewport.show_tags` AND `show_tags_selected_only` both default **True** (they were both False), so a fresh scene labels what you select and nothing else — either default alone is worse (off hides the labels the author wrote; all-on buries a large scene in text). Three surfaces must agree: the two Display checkboxes and the View menu action, all synced through `_set_tags`. **Headless tools that want ALL tags must now say so explicitly** — `export_frame.py`, `benchmark_frames.py` and `capture_tour_shots.py`'s 12b shot set `show_tags_selected_only = False`, since a headless render has no selection and would otherwise draw zero tags. Native spec: `glyphviz-skill/references/tags-and-labels.md`. `gaiaviz-skill/references/format/Tag-Format.md` covers only the legacy `np_` companion-file dialect — reach for it when reading genuine GaiaViz files, not when generating.
- **Transform gizmo (red/green/blue X/Y/Z handles)** — arming Move/Rotate/Size draws arrows/rings/bars on the first selected visual node; dragging one constrains the edit to that axis and tracks the cursor, and the whole selection takes the same field change (GlyphViz Web's multi-select rule). Purely **additive**: a press that misses every handle still gets the pre-existing free-form axis-checkbox drag, so nothing was replaced. View > Show Transform Handles hides them without disarming the mode. The Properties panel's "Lock X/Y/Z together" checkbox also governs Size mode (`Viewport.uniform_scale`): any Size drag then applies one FACTOR to all three axes — deliberately not the panel spin boxes' equalize-the-values rule, which would flatten a 3:1:1 glyph to a cube on the first pixel. Rotate rings are built perpendicular to their OWN axis (`gizmo.perpendicular_basis`), never spanned by the other two — the gizmo's three rotation axes are non-orthogonal in general, and spanning ring A with axes B and C squashed it to a sliver near gimbal lock (Jeff's 2026-08-03 report); coincident rings now correctly *mean* gimbal lock. Suppressed on Links, in Camera Mode, and in stereo. The per-mode handle frames are the whole point and are NOT the node's local axes: Move follows the numerical gradient of `topology.placement_offset` (so a Sphere parent's red arrow is the longitude tangent), Rotate differentiates the rotation matrix (so HTR's `rotate_y`→Z-rotation is handled), Size uses the world_basis columns. Qt-free math in `glyphviz_core/gizmo.py`; tests `tests/test_gizmo.py` (math, pinned against the real engine) + `tests/test_gizmo_viewport.py` (interaction, no GL context needed — camera matrices are seeded and checked against a real paint). Docs: `glyphviz-docs/docs/reference/viewer-navigation.md#transform-handles`.
- **Camera Mode (free flight)** — **C** toggles it (this *displaced* the old plain-C camera cycling, which moved to **Shift+C**; reverse-cycling is gone, the Camera toolbar covers direct jumps). Left-drag is ANTz-style **rate flight** on ANTz's opposite button (reworked 2026-07-30 at the test group's request, replacing the original per-move drag with transient banking — banking is gone entirely): the press point becomes a bearings origin, the held cursor offset from it sets a continuous forward/back speed and turn rate (integrated per repaint tick in `_apply_fly_drag`, so motion continues while the mouse sits still; 3px dead zone), and flight is locked to the horizontal plane it starts on (translation follows the heading with pitch dropped). Right-drag looks around from where the camera stands (ANTz's left-button gesture), both buttons slide, wheel flies. Same orbit rig underneath: flight holds `_cam_distance` fixed and moves the *target* end of the arm (`_reaim_about_eye`, `_translate_rig` in `viewport.py`), so the target rides in front of the camera instead of pinning it. Locked axis cameras can't fly; Follow Selected is cleared on entry. Tests: `tests/test_camera_mode.py`.
- **Drag and drop** — dropping a node CSV, a scene folder, or a **zip** onto the window loads it; Shift+drop merges instead of replacing. Also takes `.pdb`, mesh files, and image/video folders. All routing decisions live in the Qt-free `glyphviz_core/drop_router.py` (`resolve_drop()` returns an ordered `DropPlan`; `MainWindow.apply_drop()` executes it), so they're testable headlessly — `tests/test_drop_router.py`. A folder/zip drop only ever *actions* the node CSV: the tag file, ch-map/ch-tracks pair, audio manifest, and `media/` textures are all discovered from that path by the existing loaders. Node CSVs are identified by **columns, not filename**, so arbitrarily-named files load and companions never masquerade as scenes. Zips extract beside themselves (never overwriting an existing folder), falling back to temp when that's unwritable; entries with absolute or `..` paths are refused. Docs: `glyphviz-docs/docs/reference/drag-and-drop.md`.
- **Fetch Basemap** — World Grid panel button (flat grids only): measures the grid children's lon/lat bounding box, downloads map imagery for that window from a free tile service (OSM streets / Esri satellite / OpenTopoMap terrain — no API key), reprojects Web Mercator → plate carrée so the map lines up with child placement, stamps the required attribution into the corner, writes `media/zz_basemap_grid<id>.png` beside the CSV, and sets the grid's extents + `texture_id` (other nodes' `texture_id`s auto-shift when the insertion changes media numbering; refetch overwrites in place, no shift). Qt-free logic in `glyphviz_core/basemap.py` (tile cache in `%LOCALAPPDATA%\GlyphViz\tile_cache`, 60-tile cap per fetch); dialog+worker in `glyphviz_gl/basemap_dialog.py`; tests `tests/test_basemap.py` run offline with an injected fetcher. Antimeridian-crossing windows unsupported. Docs: `glyphviz-docs/docs/reference/basemaps.md`.
- **Minimum glyph size is now opt-in (2026-08-11)** — GlyphViz's earliest commits clamped every glyph's rendered scale (`scale_* × base_scale`) to **0.2 per axis** so a near-zero-scale node stayed clickable, which silently overrode authored data at every one of the three places draw scale is built. The clamp is now `Scene.scale_floor`, **default 0.0 (off)**, switchable at runtime via `Viewport.enforce_scale_floor` ← the Properties panel's Global Scale group checkbox and View > Enforce Minimum Glyph Size (both surfaces sync through `MainWindow._set_scale_floor`). Constant: `scene.DEFAULT_SCALE_FLOOR`. If a new code path computes rendered scale it must read `scene.scale_floor` — do NOT hardcode 0.2 again; the three existing paths (`_bake_draw_data`, `_bake_draw_rows`, `node_world_matrix`) plus the viewport's `_radius_of` framing hint are pinned against each other in `tests/test_scale_floor.py`. World Grid footprints stay exempt whatever the setting. Authoring guidance is unchanged (keep visible scales ≥ 0.2) so a scene reads the same with the option either way — that's why no example needed rebalancing.
- **Glyph Composer preview camera holds still (2026-08-13)** — `Viewport.set_nodes()` auto-frames, which is right on scene open and wrong on every keystroke in the Composer: zooming in on a detail and being yanked back to a distant overview on the next edit made close-up work impossible (Jeff's 2026-08-13 report). `_do_preview()` now snapshots `camera_state()` across the rebuild and `restore_camera_state()`s it. Re-framing is explicit: the **Reset View** button on the Preview header, a freshly-loaded template, and the first preview of all (`_camera_framed` guards that first one).
- **Camera smoothing (2026-08-14)** — optional ANTz-style navigation "inertia". `Viewport.camera_smoothing_tau` (seconds, **default 0 = off**) + `camera_smoothing_scope`, driven by the Properties panel's Camera group (slider + Off/ANTz presets + an "Applies to" combo). Requested by former ANTz users (the glide made demos look smoother) and, more importantly, because it buffers hand tremor — Dr. Warner reported Parkinson's patients benefiting from ANTz's version. **ANTz's actual mechanism, read from the source at `repos/antz/`**: two independent smoothers — a 10-cycle boxcar average of raw mouse deltas (`npUpdateMouse`, npmouse.c:162-195, every camera mode; the tremor filter) and a first-order low-pass on the camera's *world position* while "targeting" (`npCameraTranslate`, npengine.c:405-447), engaged by the L+R combo drag via `npSetCamTarget`. The second one is what Jeff disliked: ANTz eased POSITION while applying the orbit angle and zoom instantly the same frame, so the eye chased a solution the aim had already left and the orbited object swung out of frame for ~1.5s. GlyphViz fixes that by easing the whole rig **coherently** — azimuth, elevation, distance and target under one time constant — verified: the eye stays on its orbit sphere to 5.7e-14 through a full glide. The filter is `1 - exp(-dt/tau)`, exactly frame-rate independent (ANTz's `0.05*(65/(fps+5))` fudge is not, which is why its smoothing was heavier in its early slower years); the boxcar is deliberately NOT ported (pure latency + ringing, and it can't produce coast-to-rest). Architecture: `_cam_*` stays the ACTUAL rendered camera so **every reader is untouched** (matrices, picking, distance-scaled drag speeds); gestures write `_cam_goal_*` and end with `_settle_camera()`, which collapses goal onto actual unless smoothing covers that gesture — so tau=0 is bit-identical to the pre-feature code. Every gesture first calls `_adopt_direct_camera_writes()` (snap the goal from the actual **when settled**), which is what keeps code that assigns `_cam_*` directly — the Glyph Composer preview, several tests — working; mid-glide the goal wins instead (`_reconcile_camera_goal`). Programmatic moves (presets, `set_camera`, auto-framing, focus, flight, restore) snap via `_snap_camera_goal()`. **Follow Selected is the one exception and must stay one (fixed 2026-08-17):** it runs EVERY frame from `paintGL`, so calling `_snap_camera_goal()` there re-pointed the azimuth/elevation/distance goals at the lagging actual and erased any in-progress glide on the very next repaint — with smoothing on and F enabled the camera was locked solid (verified: 30 frames of orbit drag moved it 0.0°), and `_camera_settled()` reading True also released the repaint timer the glide needed. `_apply_follow_target` now writes the **pivot only**, to actual and goal together (still unsmoothed — following a moving node tracks a source, not a hand tremor), so orbit and zoom stay live exactly as the View menu promises. Pinned by `test_following_navigates_exactly_as_not_following`. **Camera Mode is excluded outright** — rate flight is already integrated per tick and re-derives the rig from the current eye, so a lagging actual would curve the flight path. A still-settling camera holds the repaint timer open (`_update_render_timer_state`) and releases it at sub-pixel tolerance (`is_settled`: 0.05° ≈ 1px at a 60° FOV; a tighter tolerance idle-spun the timer for 3s). Qt-free math in `glyphviz_core/camera_smoothing.py`; tests `tests/test_camera_smoothing.py` (filter math) + `tests/test_camera_smoothing_viewport.py` (wiring, incl. "off is off") + `tests/test_camera_smoothing_gui.py` (panel). Docs: `glyphviz-docs/docs/reference/viewer-navigation.md#camera-smoothing-optional-inertia`, `properties-panel.md`. **Session-only, and deliberately so** — Jeff considered making it a persisted user preference and decided against it for now (2026-08-14): "it is currently the only one, so let's keep it in the GUI." There is no QSettings anywhere in the app; revisit when a *second* user preference appears and that layer starts earning its keep, not before. Jeff verified the feature the same day; note that ANTz's **tiny settle tolerance** was his specific complaint ("it had to settle and lock before the camera could comfortably orbit"), so `is_settled`'s sub-pixel tolerance is the fix for the reported problem, not an incidental tuning choice. A left click/drag halting an in-progress glide is emergent (at the default combo-only scope a single-button orbit is unsmoothed, so it lands the glide immediately) and Jeff likes it — don't "fix" it.
- **Wrapped new-object placement + Placement Step (2026-08-14)** — ANTz's row-wrapping rule for auto-placed new objects, with the step exposed. `glyphviz_core/placement.py` (Qt-free): `wrapped_grid_offset(index, step)` places children by ordinal, `step_from(x, y, step)` places roots relative to the previous one, and the two walk the SAME lattice (pinned by a test that steps 200 times and compares) so a run of N and a run of Shift+N lay out identically. `translate_x` steps, and when the next step would reach `PLACEMENT_WRAP` (360 — one lap, i.e. the first object's slot on any circular topology) it restarts at 0 and `translate_y` takes the step instead: a Cartesian parent arrays into a grid, a Sphere/Torus/Cylinder parent starts a new ring instead of stacking. **ANTz's source rule** is `npNodeNew`, npnode.c:363-384 — `translate_x = -15 * siblings`, y bumped every 24 children (24 × 15 = 360). Two deliberate divergences: y is NOT folded back into -180..180 (ANTz did, npnode.c:378-384, and so eventually reused slots — GlyphViz keeps growing a taller grid), and the step is a GUI field instead of a hardcoded 15. GUI: Properties > Create > **Placement Step** spin box (`MainWindow._new_step` → `_placement_step()`), `DEFAULT_PLACEMENT_STEP` = **5.0**, which preserves the historical child spacing (and the guided tour's screenshots); the ROOT step therefore changed 10 → 5. Root placement also switched from `max(translate_x) + 10` to "one step on from the last root CREATED (highest id)" — after a wrap the largest x is back in the previous row — and now skips World Grids (a grid is the surface, not a member). Links (type 7) no longer consume a child slot. Five call sites share the two helpers: `_create_root_node`, `_create_child_node`, both `_paste_clipboard` branches, `_load_mesh_path`. Also in the same panel row group: **Placement Z**, the `translate_z` a new object is born with — TWO spin boxes (`_new_root_z` / `_new_child_z` → `_placement_z(is_child)`), defaults `DEFAULT_ROOT_Z` = 0.0 and `DEFAULT_CHILD_Z` = 5.0, deliberately not one field: the axis means height above the world plane for a root but offset off the parent for a child (radially outward on Sphere/Torus/Cylinder), so a root at 5 would hover off the grid while a child at 0 would sit INSIDE a topology-None parent. Tests: `tests/test_placement.py` (lattice math) + `tests/test_placement_gui.py` (real MainWindow, headless). Docs: `properties-panel.md#create`, `viewer-navigation.md`, guided tour §5/§8.
- **Save Selection (2026-08-14)** — File > Save Selection As… (Ctrl+Alt+S) writes the selected nodes to a node CSV of their own. **The whole feature exists because of one fact**: `topology._resolve_hierarchy` silently treats a node whose `parent_id` is absent from the file as a ROOT, and a root's `translate_x/y/z` IS its world position with no topology offset — so a naively-saved subset relocates everything (a Sphere child's lon/lat/altitude reloads as literal world XYZ; a World Grid child lands off the map). Qt-free `glyphviz_core/selection_export.py`, shaped like `scene_merge.py`: `plan_selection()` resolves membership without copying (so the dialog previews live on a 100k-node scene), `build_selection()` materializes. Membership = selection + descendant closure (checkbox, on; the `_delete_selected`/`_copy_selected` rule) + links with BOTH ends inside (auto-added even when unselected) + the type-0 World row (never bulk-selectable, carries the scene look). One-ended links are dropped (existing Copy/Paste + merge rule); `branch_level` is restated via `scene_merge.recompute_branch_levels` (promoted from private for this). **ids are preserved**, unlike merge's rebasing — `record_id` and channel bindings stay coherent for free. Three detach policies for a top node whose parent stayed behind, default **bake**: `translate` ← world position, `rotate`/`scale` ← decomposing `world_basis` into `R @ diag(s)`, written as `rotation_mode = EULER_XYZ`. **Exact, and here is why**: `world_basis = parent_basis @ child_local @ diag(scale)` is what every descendant composes off (own basis AND, through `offset_basis`, position) and is also the draw matrix over `base_scale` — preserve it and the entire subtree is pinned, rod cap offset and World Grid footprints included. Two reported (never hidden) limits: a rotated non-uniformly-scaled ancestor SHEARS the basis, which no rotate+scale pair expresses (`decompose_basis` returns a shear magnitude, `approximated_ids` counts it), and rates change frame of reference (`animated_detached`). A third is inherent to the format, not the code: the bake is exact only at the `base_scale` it ran at. Companions: tag CSV always (name convention via the new `csv_reader.companion_tag_path`/`unstamped_stem`), plus a filtered ch-map/ch-tracks pair (`channel_loader.export_channel_subset` filters at the FILE level so unparsed columns round-trip; channel ids from the new `channel_engine.channel_ids_for_nodes`). Deliberately NOT stamped with a timestamp — Save/Save As/K stamp because they snapshot a scene, this exports to a name you chose. GUI: `glyphviz_gl/save_selection_dialog.py` (options + live preview), `MainWindow._save_selection_as`. Tests: `tests/test_selection_export.py` (math + rules, incl. the round-trip fidelity check through real Scene objects) + `tests/test_selection_export_gui.py` (wiring, headless). Docs: `glyphviz-docs/docs/reference/save-selection.md`.
- **Link geometries (2026-08-15)** — a Link (type=7) renders whatever `geometry` it carries, stretched between its two ends, instead of only a line or a prism. **ANTz's own behavior, read from `repos/antz/sdk/src/io/gl/npgldraw.c:961` (`npDrawLink`)**: translate to A, `Rz(atan2(uy,ux) - 90°)·Rx(asin(uz) + 90°)`, `glScalef(ratio, ratio, distance × 0.5)`, then +1 unit along the axis — i.e. `npGLSurface` draws the node's ordinary geometry with a bespoke matrix. `ratio` is the thickness on **both** cross-axes (Jeff's call, and ANTz's — NOT scale_x/scale_y; a link's own translate/rotate/scale stay inert). Qt-free math in `glyphviz_core/link_geometry.py`. **One deliberate improvement over ANTz**: the glyph's *own* local Z extent is mapped onto the A→B segment (`local_z_span`), which is identical to ANTz's fixed `distance × 0.5` for every -1..1 shape and fixes Pin, whose apex is its local origin (ANTz papered over that with a conditional -1 nudge in npGLSurface, npgeometry.c:205, leaving a pin link hanging past its B-end). **Mode is chosen by `geometry` alone** — no new column, so a link's look travels with the CSV. `LINK_LINE_GEOMETRIES` = {27 Line, 28 Prism, **22 Point**}: Point is in there because a fixed-pixel sprite has no extent to stretch AND because it keeps the GTDB Org_Event_Network example's 6400 links rendering unchanged. That set is the entire back-compat surface — every example file uses 27/28/22. The one other pre-existing writer was `pdb_loader.py`, which set GEO_SPHERE on bonds (meaningless when every non-Line id fell through to the line renderer, so they drew as 1px lines); **it now says GEO_CYLINDER and PDB import produces true ball-and-stick** — Jeff approved that the same day, and `ratio=0.05` was already a sensible stick radius. This is the one deliberate visual change to pre-existing output in the whole feature; `glyphviz-docs/docs/assets/examples/protein-import.png` was recaptured to match (`tools/capture_example_shots.py --only protein-import`). Set GEO_LINE there to go back to lines. O/Shift+O cycles a link through the full range (skipping Mesh + Point, `_LINK_SKIP_GEOS`); ordinary nodes still skip the two line ids. Glyph links are now pick-solid (same matrix as the visible pass) and draw a selection box; line/prism links keep their long-standing no-box behavior. **Same-day fix, and it is older than this feature**: `_render_pick_scene` drew a unit "fallback pick sphere" at `world_pos(link.id)` so a link with a missing B-end stayed clickable — but a link's own position IS its A-end's (translate 0,0,0, parent_id = the A-end), so that sphere sat exactly on a real node at that node's own scale and was drawn AFTER it. Cube and Octahedron are inscribed in the unit sphere, so it swallowed them: measured through the real pick FBO, an A-end node had **zero** pickable pixels; a Sphere node tied on depth and survived by luck, which is why Jeff experienced it as angle-dependent and had been working around it for sessions. The sphere bought nothing — when an end is unresolvable the visible pass draws nothing, so it let an INVISIBLE link outrank a visible node. Removed; the loop is now `Viewport._draw_link_pick_targets()` with one invariant: **this pass draws what the visible pass draws.** After the fix A-end and B-end pick coverage is pixel-identical and matches a no-link control exactly. If you touch this, keep the invariant — do NOT reintroduce a pick target at a link's own position. The Properties panel's ratio spin box went 1.0 → 10.0 max, since a link spanning tens of units needs a thickness to match (>1 is degenerate on a torus, so you have to type past 1.0). Perf is deliberately the user's problem — Jeff's explicit call, capability over frame rate. Tests: `tests/test_link_geometry.py` (math, incl. a column-for-column equivalence check against ANTz's rotation composition) + `tests/test_link_geometry_gui.py` (cycling + render dispatch + the GL_LIGHTING state contract, headless). Docs: `glyphviz-docs/docs/reference/geometries.md#geometry-on-a-link-node`, `glyphviz-skill/references/node-csv-format.md`.
- **Interior geometries (2026-08-24)** — four ids appended after `GEO_LINE_PRISM`: `GEO_CUBE_INTERIOR` (29), `GEO_SPHERE_INTERIOR` (30), `GEO_CYLINDER_INTERIOR` (31), `GEO_CYLINDER_INTERIOR_OPEN` (32); `GEO_COUNT` 29 → **33**. Each draws the shape's INSIDE surface, for a 360° video sphere / cylindrical panorama / video room. **Chosen by `geometry` alone** — same rule as link geometries, so the look travels with the CSV, saves and loads with no new column, O-cycles, and is Channels-bindable for free. Jeff's alternative was a new node **type=8** meaning "culling off"; the measurement that settled it: **culling-off cannot un-mirror the image**. Viewing an outward-mapped surface from behind is inherently a mirror view (verified by rendering a texture reading "R" — it comes back reversed), and the un-mirroring lives in the vertex/UV data, i.e. in the display list, i.e. in the geometry. A type flag can only toggle global GL state. Type=8 was cheap mechanically (every branch on `type` in core/gl/xr is a *negative* test — `== GRID`, `== LINK`, `in NON_VISUAL_TYPES` — so an unknown type already falls through to the ordinary-glyph path), but it also spends a non-composable axis (no interior Link or Grid), can't fix normals or double-blending, and `type` isn't even editable in the GUI. **Implementation**: sphere/cylinder are `geometry._mirrored(...)` — a `glScalef(-1,1,1)` recorded into the display list, which flips winding (negative determinant) AND texture handedness in one op, reusing the exact existing builders. **Normals are NOT flipped by it** — the inverse transpose of diag(-1,1,1) maps a sphere's outward normal to the outward normal at the mirrored point, still outward. Measured: a white interior sphere rendered 0.505 grey, exactly the two ambient terms (0.2 global + 0.3 GL_LIGHT0) with zero diffuse, identical whichever way the camera faced. So all four interiors are wrapped in `_unlit()` — full brightness, the same call `_draw_world_grid` makes for a map. Flipping the normals instead was rejected: `GL_LIGHT0`'s position is set under an identity modelview, making it an **eye-space headlight**, so a lit interior would carry a bright patch sliding across the video as the viewer turned. `_unlit` uses `glPushAttrib(GL_LIGHTING_BIT)`/`glPopAttrib`, NOT a `glIsEnabled` restore (a query inside `glNewList` runs at compile time and bakes the wrong answer) and NOT a bare `glEnable` at the end (interior ids aren't in `WIRE_TO_SOLID`, so they run in the color-ID pick pass, which needs lighting to stay off — the GEO_POINT bug). The cube gets a bespoke `_draw_cube_interior` because ONE reflection cannot un-mirror all six faces — the two perpendicular to the mirror axis would read backwards; it builds each face from a screen-space basis (`right = axis × up`) for a viewer at the centre, which lays u right / v up and winds CCW-from-inside for free. Floor and ceiling take OPPOSITE y in `_CUBE_INTERIOR_FACES` and that is not a typo — an orbit camera's screen-up points away from its azimuth looking down and along it looking up, so same-y left one of the two 180° round (measured). **Interiors stay single-sided** — culling stays ON (GEO_MESH remains the only geometry that disables it), so one fragment per pixel and alpha still behaves; from OUTSIDE you see the far inner wall, like a bowl (visible and pickable, NOT invisible). Caps: `_draw_cylinder(..., caps=True)` default preserves every existing call site; the capped/open pair is exposed as a Properties panel **End caps** checkbox that simply swaps the id (`geometry_data.with_caps`/`has_caps`/`CYLINDER_INTERIOR_BY_CAPS`), touching only interior cylinders in a mixed selection. `link_geometry.py` needed no change (interiors are -1..1, so `DEFAULT_LOCAL_Z_SPAN` is right) — a link with an open interior cylinder is a tube you fly through. World Grids are untouched: `grid_is_globe()` still keys on {2,3}, so an interior globe grid (a planetarium with lon/lat children) is a possible follow-up, not something this shipped. Tests: `tests/test_interior_geometry.py` (winding/normals/UV handedness via the GL stub-recorder, with the exterior cube as the control) + `tests/test_interior_geometry_gui.py` (checkbox ↔ dropdown agreement, headless). Docs: `glyphviz-docs/docs/reference/geometries.md#interior-geometries-seen-from-within`, `properties-panel.md`, `glyphviz-skill/references/node-csv-format.md`.
- **Large-scene render fixes + terrain module (2026-09-12)** — found while budgeting the San Diego River Watershed scene (69,676 nodes: HEAD renderer 89.3 ms/frame → 3.3 ms, **0 of 1,440,000 pixels different**, checked through real GL against a HEAD copy of viewport.py). Four fixes, each pixel-identical: (1) **zero-scale cull** — `viewport._draws_nothing(node, radius)`: the draw AND pick loops skip a glyph whose `node_draw_data` radius is exactly 0 (rendered scale 0 on all axes, after base_scale and the opt-in scale floor), EXCEPT `GEO_POINT` (fixed-pixel sprite), wire ids (a zero-length line can rasterise a pixel), and textured nodes (VideoManager pauses a video no draw call asks for). A skipped node still counts toward the backslash draw limit. Authoring rule that follows: **Surface/Plot vertices at scale 0 with a solid geometry** — `hide=1` drops them from the mesh and `color_a=0` makes the mesh transparent. (2) **TOPO_PLOT retained** in display lists (`_PlotEntry`/`_plot_dls`/`_plot_entry`/`_emit_plot_line`, mirroring `_SurfaceEntry`); channel-bound plots re-emit per frame. (3) **Latent bug in e22d51f's surface cache, fixed**: its key lacked `_ch_dynamic_rev`, so a channel bound AFTER the first paint (a channel file loaded later, a Channel In rebind) kept replaying a frozen mesh.
